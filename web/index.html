02 / Evaluation protocol

One model. One declared run.

Public white-box suite
01

Choose the questions.

Assign a subset or the full frozen suite. The class definitions and cited baseline are public. The release audit records which questions were open at the cutoff.

02

Run the model.

Choose an explicit model version and token and time limits. The OpenAI and Anthropic adapters preserve prompts, answers, proof files and provider usage.

03

Review the evidence.

Check the run record and each proof. New ordinary claims use the Lean proof checker; independence metatheorems require explicit expert review. Existing cited results are trusted.

04

Count the resolutions.

Combine accepted proofs with the frozen implications. Count each resolved pair admitted by the cutoff audit once. A reviewed run with no solutions can score zero.

05 / Scope & provenance

What the score measures.

The benchmark measures an AI run's ability to resolve open questions about total-language complexity classes. It is intended for mathematical reasoning beyond the current public baseline. It does not attempt to cover every kind of progress in complexity theory: promise-only separations, individual algorithmic speedups, search problems and fixed-exponent lower bounds can fall outside this suite.
