# Independent review of the seven new classical models

**Result: no blocking semantic defect found.** This review covers BPL, UL, PL, PSharpP, CH, UniformNC1 and ExistsR in provisional v0.4.0. It reads their operational definitions and the underlying tape, counting, oracle and output-transducer machinery. It does not treat successful compilation, a familiar class name or an opaque predicate as evidence of equivalence with the intended class.

The review produced fifteen retained Lean checks in `lean/InclusionBench/ClassicalSemanticChecks.lean`. They compile independently with Lean 4.19.0 and one worker. Two are general work-tape invariants; the others probe branch weighting, halting, binary addressing, query encoding and malformed real syntax. The companion JSON records exact source hashes, names and scope. The full build also checks the authors' supporting lemmas, including parser round trips, formula compilation and duplicate oracle-branch counts.

## BPL, PL and UL: clocks, work space and branch mass

`LogspaceClasses.BPL` combines one finite fair-coin machine's polynomial all-branch clock, bounded-error decision condition and work-space bound on **every random prefix**. The prefix quantifier ranges over every Boolean list of length at most the clock. It therefore cannot ignore a space violation on a rejecting path or a rare path. The same machine meets both bounds.

Randomness is streamed: each active step consumes one fair bit and chooses one of exactly two actions. The machine's transition function receives its state, current input symbol and current work symbol; it cannot reread the coin list or inspect a random-tape address. Halting pads the state without changing it. Consequently, early-halting branches receive the probability mass of all their unused random-bit extensions. An independent example accepts immediately on one first-coin outcome and tosses a second coin on the other. The formal acceptance count at horizon two is **3 of 4**, while counting variable-depth leaves uniformly would incorrectly give 2 of 3. The test also proves total accept-plus-reject mass is four.

`PL` uses the same finite fair-coin machine and resources, with the strict condition `2^t < 2 * acceptCount`. A tie rejects. The independent one-coin example verifies this boundary. There is no inverse-polynomial gap requirement, no postselection denominator and no probability distribution obtained by normalizing arbitrary nondeterministic branch degrees.

For `UL`, `SharpL` counts a polynomial-clocked nondeterministic machine's accepting paths. The machine's successor list retains duplicate actions, and the recursive sum retains their multiplicity even when they reach the same configuration. Reachability is a proposition and thus forgets multiplicity, but it is used only for universal halting and space obligations. The counting function does not use that proposition as a set of paths. The independent check confirms that two duplicate accepting actions count twice and that moving the fuel horizon past their halt does not create additional paths. Requiring the count to be at most one on **every** input gives unambiguity, rather than a US-style exact-one condition that permits multiple accepting paths on nonmembers.

The work tape stores the entire visited interval, including blank cells. Its footprint counts both lists and the head cell. The new general lemmas prove that a write/move never decreases this footprint and increases it by at most one. Thus blank erasure cannot hide previously visited space, and no primitive step jumps across uncharged work cells. The read-only input head is clamped between the two endmarkers, so it does not become an unbounded free counter.

The clock functions in these definitions need not themselves have an executable encoding. This does not provide advice: one machine is fixed for the entire language, and the clock only certifies a polynomial upper bound on all its paths. A horizon shorter than an active path fails the halting condition. A horizon after all paths halt has the same acceptance answer and path count. Replacing the bound by its dominating explicit polynomial therefore preserves the language. The standard finite-machine normalization, including binary branching, is a trusted model correspondence; arbitrary finite branching adds only a constant simulation factor and preserves accepting-path multiplicity.

## PSharpP and CH: actual oracle machines

`CountingHierarchy.PSharpP` is operationally `POracle PP`, namely P^PP. The oracle is one total language chosen outside the quantifier over inputs. It is not a table chosen separately for each length. The finite machine writes the query tape and receives a single Boolean answer only through a designated query action.

A query reads the visited tape interval in order and omits blank cells. This convention is explicit and computable. The independent example checks the order when blanks occur on both sides of the head. In T steps the machine can visit and write only O(T) query cells. Compressing those cells into an ordinary contiguous query costs polynomial time and introduces no nondeterministic branches, so this representation does not grant a counting oracle for free or change path multiplicities. Query tapes persist after a call, but a standard oracle machine can simulate that behavior and can explicitly clear them within polynomial time.

The equality P^PP = P^#P is an external textbook bridge, not a definitional identity of PP with the function class #P. A #P answer has polynomially many bits and can be recovered by polynomially many adaptive PP threshold queries. Conversely, exact counts decide a PP predicate. The class does not claim one PP answer returns a whole integer.

`PPWith` uses a difference of two accepting-path counts from concrete oracle machines. Each machine must halt on every branch for the fixed oracle. A query has one successor determined by actual membership; the nondeterministic list still represents the computation's own choices. The author's compiled duplicate-branch example verifies count two independently of which oracle is supplied. An oracle-specific polynomial bound can be replaced by an explicit external clock, giving the usual convention that the machine also halts under other oracle answers without changing the counted paths for the chosen oracle.

`countingLevel` has P at level zero, PP at level one, then applies the relativized PP operator to the preceding level. `CH` chooses one natural-number level for the whole language. The existential quantifier is outside the input semantics, so the level cannot grow with input length. The direct level-one definition uses the standard PP^P = PP correspondence; no CH collapse follows from this choice. Each level chooses fixed oracle languages from the preceding class, as in the standard oracle definition. No unrelativized containment is substituted for an outer oracle computation by these definitions.

## UniformNC1: random access and uniformity

`AlternatingLogtime.Machine` has finite control and a fixed finite number of ordinary work tapes. Its transition arguments range over finite types. Even though a Lean function supplies the transition table, it contains only finitely many entries and cannot hide an arbitrary input language.

The input port reads the bit at the binary address on a separate tape. This is the sole random-access operation. The transition table sees the addressed input bit, the local address-tape bit and the ordinary work-tape heads; it cannot inspect a whole work tape or apply arbitrary arithmetic. Address bits have fixed significance relative to the left endpoint. Moving the head does not shift them. The independent checks verify that a stored address five remains five after head movement and that writing bit four gives address sixteen.

Every head moves at most one cell per transition. The address tape is initially empty, and ordinary tapes are blank. Nothing initializes an input-dependent address or advice string. After t steps, only O(t) address and work cells can have been visited. A missing input length is not an obstacle to the conventional model. The local-head construction is spelled out below; it takes O(log n) transitions and does not assume a unit-cost binary increment or repeated rescanning. The address decoder is the semantics of a standard random-access input port, not an extra operation on arbitrary tape contents.

To recover the length, first query address zero, which detects the empty input. For a nonempty input, write one at index cell zero and shift that single one right until the address is out of range. Each doubling uses two local transitions: clear the present bit and move right, then write one and test the new address. This finds an exponent k with 2^k ≥ n. Clear the high bit and descend through positions k−1,…,0 once. At each position, tentatively set its bit; retain it if the input port returns `some`, or clear it if the port returns `none`, then move left. The higher bits form a valid prefix and lower bits are zero, so the final address is n−1. Each position costs at most two local transitions. Because the index tape itself exposes no head-position flag, an ordinary work tape carries a marker at its origin and moves in lockstep with the index head. That marker detects the final position without adding a scan. A single carry pass starting at the least significant bit computes n; returning the heads to the origin costs one further traversal. Singleton inputs are the k=0 boundary case. The number of head traversals is constant, so this argument has no hidden O(log² n) term. This is an explicit mathematical machine construction, not an additional compiled Lean theorem.

The machine's finite computation tree is evaluated by disjunction at existential states and conjunction at universal states. Terminal states use an explicit Boolean answer, including terminal universal states; they do not accept merely because an empty conjunction is true. At zero remaining fuel a nonterminal state rejects, but every branch is separately required to halt by that horizon. The independent check verifies that even an accepting state flag cannot override this nonterminal rule. The author's two-branch examples distinguish existential acceptance from universal rejection.

The random-access design matches [Buss, §2, pp.4–5](https://mathweb.ucsd.edu/~sbuss/ResearchWeb/Boolean/paper.pdf): a multitape alternating machine with a binary address tape and input access in every state. The exact binary tape conventions and their standard constant-factor simulations remain a model bridge. The intended circuit interpretation is **U_E DLOGTIME-uniform NC¹**, via ALOGTIME. It must not be weakened to mere DLOGTIME recognition of the direct-connection language U_D; [Behle–Krebs–Lange–McKenzie, Remark 1](https://eccc.weizmann.ac.il/report/2011/095/revision/1/download/) explicitly distinguishes those notions. This endpoint is also separate from the existing nonuniform NC1 class.

## ExistsR: finite syntax, genuine real witnesses and computable reductions

`RealSyntax` encodes a finite postfix program over integer constants, variable references, addition, multiplication, negation, equality, strict order and Boolean connectives. Coefficient magnitudes are binary bit strings. Unary metadata stores record lengths, variable indices and the variable count; it does not expand a binary integer coefficient into its numeric magnitude. The independent example verifies the significance of a leading-zero coefficient bit string.

The program has no duplication or macro instruction that could denote an exponentially larger hidden formula. Each operation consumes its operands and builds one syntax node, so the assembled formula has size bounded by the program's syntax size. The compiler lemmas show that every finite term and formula can be represented. Standard sparse-polynomial or quadratic-system encodings can use auxiliary variables for powers and intermediate products; the equivalence is a trusted reduction theorem, not a claim that the current parser directly implements every historical syntax.

`deserialize` checks record boundaries, instruction payload types, Boolean coefficient digits and exact reserialization. The parser's round-trip and serialization-injectivity theorems prevent one word from ambiguously denoting two input objects. Leading zeros in a coefficient may yield different input objects with the same numeric meaning; this ordinary redundancy is harmless. The assembler requires exactly one final formula. Independent checks reject an invalid coefficient digit, a type-mismatched operation and an unused extra stack entry.

`Instance.valid` checks every variable instruction against the declared finite variable count. `Satisfiable` requires that check before evaluating the assembled formula. In particular, an out-of-range variable cannot exploit the evaluator's default zero extension to create a vacuous equality. The independent out-of-range example is rejected even though its stack operations are otherwise well typed.

The witness is a function from `Fin variableCount` to Mathlib's actual real numbers. The infinite `Nat → ℝ` evaluator argument is only the zero extension of this finite tuple; no additional real coordinates are quantified. The syntax has no real constants, arbitrary functions of the witness or internal quantifiers. Boolean negation therefore remains part of a quantifier-free matrix under one outer existential real block. The author's formal examples accept x² = 2 using a real square root and reject x² = −1. They distinguish the intended domain from finite-bit rational witnesses and arbitrary arithmetic predicates.

Finally, `ExistsR` quantifies a polynomial-time many-one reduction computed by one finite output transducer. The machine starts from its fixed blank configuration, emits at most one bit per step and cannot read its output tape. Its transition table receives no real witness, oracle or interpretation function. Halting and exact output are required on every binary input at one explicit polynomial horizon; output length is formally bounded by that horizon. Thus the class contains precisely the languages reducible to this concrete real-feasibility language, subject to the cited standard encoding bridge.

## Limits of the conclusion

This review found no need to weaken or replace any of the seven endpoints. The fifteen new checks address specific ways these implementations could accidentally express a different model. They do not prove all machine-equivalence, reduction-closure or historical inclusion theorems. The remaining trusted bridges are explicit: finite-machine normalization, fair-coin/GapL characterizations, P^#P = P^PP, the standard fixed-level counting hierarchy, ALOGTIME's U_E circuit characterization, and polynomial equivalence of finite ETR encodings. The user's waiver for existing proofs permits these bridges to remain cited, but does not make future changes to their hypotheses safe without review.
